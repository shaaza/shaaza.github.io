## Objective

By the end of this week, you will have a fully configured development environment with AI coding agents installed and working. You will have completed your first agent-directed coding exercises and begun developing the interaction patterns you will use throughout Level 1.

This is a setup week, but do not underestimate it. The quality of your environment directly affects the quality of your agent interactions. A well-configured workspace removes friction; friction leads to bad habits.

## Install and Configure Claude Code

Claude Code is your primary tool for Level 1. It runs in your terminal, reads and writes files on your machine, and executes commands.

### Installation

```bash
# Requires Node.js 18+
node --version

# Install globally
npm install -g @anthropic-ai/claude-code

# Verify installation
claude --version

# Start your first session
claude
```

### First Interaction

Once Claude Code is running, try a simple task to verify everything works:

```bash
claude

> Create a Python script that prints the first 20 Fibonacci numbers.
> Save it as fibonacci.py in the current directory.
```

Watch what happens. The agent will:
1. Write the code
2. Create the file
3. Optionally run it to verify

**Your job is not to type code.** Your job is to review what the agent produced and decide if it is correct.

### Configuration

Set up your environment for productive agent interactions:

```bash
# Create a project directory for Level 1 work
mkdir -p ~/level-1-os
cd ~/level-1-os

# Initialize version control
git init
git branch -M main

# Create a .gitignore
claude
> Create a .gitignore file appropriate for a C-based operating
> system project. Include common build artifacts, editor files,
> and OS-specific junk files.
```

## Explore Alternative Tools

While Claude Code is the default, you should spend at least an hour with one or two alternatives. Understanding the landscape makes you a better practitioner.

| Tool | Type | Strengths | Setup |
|---|---|---|---|
| **Claude Code** | CLI agent | Deep context, file access, command execution | `npm install -g @anthropic-ai/claude-code` |
| **Codex CLI** | CLI agent | OpenAI ecosystem, similar terminal workflow | `npm install -g @openai/codex` |
| **Cursor** | IDE | Visual context, inline editing, chat + compose | Download from cursor.com |
| **Aider** | CLI agent | Open-source, git-aware, multi-file editing | `pip install aider-chat` |
| **GitHub Copilot** | IDE extension | Inline completions, VS Code integration | VS Code extension marketplace |

### Comparison Exercise

Try the same task with two different tools:

> "Create a linked list implementation in C with insert, delete, search, and print functions. Include a main() that demonstrates all operations."

Compare:
- How did each tool interpret the request?
- Which produced more correct code on the first try?
- How did they handle follow-up corrections?
- Which felt more natural to work with?

## Set Up Version Control Workflow

Version control is critical when agents write your code. You need to be able to:
- See exactly what the agent changed
- Roll back when something breaks
- Track the evolution of your project

### Git Workflow for Agent-Directed Development

```bash
# Before each agent session, create a branch
git checkout -b feature/scheduler-basic

# After the agent makes changes, review the diff
git diff

# Commit frequently with descriptive messages
git add -A
git commit -m "Add basic round-robin scheduler with 4-task support

Generated by Claude Code. Implements fixed time quantum of 10ms.
Task switching via context save/restore stubs."

# If something goes wrong, you can always go back
git log --oneline
git checkout main
```

> **Rule of thumb:** Commit after every successful agent interaction. If the agent breaks something in the next interaction, you can always revert.

## Project Scaffolding

Set up the directory structure for the OS capstone project. You will not start building until Week 2, but having the structure in place helps you think about decomposition.

```bash
claude

> Create a project directory structure for a minimal operating system
> written in C. The OS will have these subsystems:
> - Bootloader
> - Kernel core
> - Scheduler (process management)
> - Memory manager
> - Filesystem
> - I/O subsystem
> - Shell (user interface)
>
> Create the directory structure with placeholder README files in
> each subsystem directory explaining what will go there.
> Also create a top-level Makefile skeleton.
```

Expected structure:

```
level-1-os/
├── Makefile
├── boot/
├── kernel/
├── scheduler/
├── memory/
├── filesystem/
├── io/
├── shell/
├── include/          # shared headers / interface definitions
├── tests/
└── docs/
```

## First Exercises

Complete these exercises to build initial fluency. Each should take 15–30 minutes.

### Exercise 1: Data Structure Implementation

Ask your agent to implement a **ring buffer** in C — a fixed-size circular queue used heavily in OS development for I/O buffers.

Requirements to give the agent:
- Fixed-size buffer (configurable at compile time)
- `push()` and `pop()` operations
- Overflow and underflow handling
- A test harness that demonstrates all edge cases

### Exercise 2: Makefile Generation

Ask your agent to create a **Makefile** that:
- Compiles all `.c` files in `src/` to `.o` files in `build/`
- Links them into a single binary
- Has `clean`, `test`, and `debug` targets
- Uses GCC with `-Wall -Wextra -Werror` flags

### Exercise 3: Bug Introduction and Detection

Ask your agent to write a program with **an intentional memory bug** (double free, use-after-free, buffer overflow). Then, in a *separate session*, give the buggy code to the agent and ask it to find the bug.

This exercise teaches you two things:
1. How agents introduce bugs (the patterns they fall into)
2. How agents detect bugs (what they catch and what they miss)

## What to Observe This Week

As you work through setup and exercises, keep a mental (or written) log:

| Question | Why It Matters |
|---|---|
| How specific do your prompts need to be? | Calibrates your communication style |
| When does the agent ask for clarification vs. guess? | Tells you about confidence patterns |
| How often does generated code compile on first try? | Sets your expectations for review burden |
| What kinds of errors does the agent make? | Informs your verification strategy |
| When do you feel the urge to type code yourself? | Identifies your trust boundaries |

- [ ] Three exercises completed (ring buffer, Makefile, bug exercise)
