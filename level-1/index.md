## The Question

What happens when you write **100% of your code with AI agents**?

Not 50%. Not "AI-assisted." Every line of code generated by an agent, directed by you. You do not type code. You describe intent, review output, and steer.

This is not a gimmick. It is a forcing function. By refusing to hand-write code, you are forced to develop a completely different set of skills: **decomposition, specification, verification, and orchestration.** These are the skills that matter when AI writes most of the code — which, increasingly, it does.

> "The best way to learn what AI can and cannot do is to depend on it completely for six weeks."

## Philosophy

Level 1 operates on a simple principle:

| Principle | What It Means |
|---|---|
| **100% AI-generated code** | You never type code directly. Every line comes from an agent. |
| **You are the architect** | You decompose, specify, review, and integrate. The agent executes. |
| **Learn by directing** | Fluency comes from thousands of interactions, not from reading docs about AI. |
| **Ambition by design** | The capstone is deliberately too big. That is the point. |

## Primary Tool: Claude Code

Your primary tool is **Claude Code** — Anthropic's CLI agent for software engineering. It operates in your terminal, has access to your filesystem, and can run commands.

```bash
# Install Claude Code
npm install -g @anthropic-ai/claude-code

# Start a session
claude

# Give it a task
> Create a basic round-robin scheduler in C that manages 4 tasks
```

**Alternatives you may explore:**
- **Codex CLI** (OpenAI) — terminal-based agent
- **Cursor** — IDE with built-in AI agent
- **Aider** — open-source terminal coding assistant
- **Copilot in VS Code** — inline AI pair programming

You are encouraged to try multiple tools. But Claude Code is the default, and all course examples use it.

## The Capstone: Build an Operating System

Yes, really. You will build an operating system from scratch — using only AI agents to write the code.

This is ambitious **by design**. You will not build Linux. You will not build something production-ready. But you will build something that boots, schedules tasks, manages memory, has a filesystem, handles I/O, and presents a shell. And you will do it by directing agents, not by typing C.

Why an OS?

- It has **clear subsystems** that can be decomposed and built in parallel
- It requires **integration** across subsystems with well-defined interfaces
- It is **complex enough** that no single agent session can hold the whole thing
- It forces you to think like an **architect**, not a coder
- It connects directly to everything you learned in Level 0

## The Project Arc

The OS project follows a deliberate arc over six weeks:

| Phase | Week | Activity | What You Practice |
|---|---|---|---|
| **Decompose** | Week 2 | Break the OS into subsystems | System thinking, interface design |
| **Parallelize** | Week 2 | Assign subsystems to separate agent sessions | Agent orchestration, dependency analysis |
| **MVP First** | Week 3 | Build the simplest version of each subsystem | Scoping, breadth-first development |
| **Integrate** | Week 3 | Wire subsystems together | API contracts, interface debugging |
| **Iterate** | Week 4 | Deepen each subsystem | Incremental improvement, full-system context |
| **Differentiate** | Week 4 | Add your unique feature | Creative engineering, product thinking |
| **User Test** | Week 5 | Get real humans to use it | Humility, feedback loops, user research |
| **Ship** | Week 6 | Polish, package, and release | Craft, personality, shipping discipline |

## Key Lesson: Breadth Before Depth

The single most important lesson in Level 1:

> **You don't have something working until you've built all your subsystems.**

It does not matter if your scheduler is perfect if you have no filesystem. It does not matter if your memory manager is elegant if there is no shell to interact with. The temptation is to go deep on one subsystem. Resist it.

Build thin, end-to-end slices first. Get something that boots. Then deepen.

This is also how professional engineering works at scale. And it is how AI-assisted development works best — agents are better at building a thin slice of something than they are at building a deep, perfect component in isolation.

## Agent Parallelism Pattern

When building the OS, you will run multiple agent sessions in parallel — each working on a different subsystem, all coordinated by you.

```
                    +-----------------+
                    |   YOU           |
                    |   (Architect)   |
                    +--------+--------+
                             |
            +----------------+----------------+
            |        |        |        |      |
         +--v--+  +--v--+  +--v--+  +--v--+  +--v--+
         |Agent|  |Agent|  |Agent|  |Agent|  |Agent|
         |  A  |  |  B  |  |  C  |  |  D  |  |  E  |
         +--+--+  +--+--+  +--+--+  +--+--+  +--+--+
            |        |        |        |        |
        Scheduler  Memory  Filesystem  I/O    Shell
```

**You are the architect.** You define the interfaces between subsystems. You decide what each agent works on. You review the output. You resolve conflicts when subsystems do not fit together. The agents write the code; you make the system.

This pattern — one human orchestrating multiple AI agents — is not just a course exercise. It is how significant software will be built in the coming years. Level 1 gives you practice at it before the rest of the world catches up.

## What You Will Build

By the end of Level 1, you will have:

- A working (if minimal) operating system that boots and runs
- Experience directing AI agents across thousands of interactions
- Intuition for what AI is good at, what it struggles with, and when it hallucinates
- Practice with decomposition, parallel development, and integration
- A shipped project with your name on it
